# Mira maintenance audit · October 14, 2026

## Fixed and live

The screenshot’s “update channel has not been published yet” error came from GitHub Latest pointing at an IPA-only release without `mira-updates.json`. Restored TV v0.5.22 as Latest and verified the shared manifest against every referenced GitHub artifact’s SHA-256 digest and size, including both Mac architectures. The channel currently lists iPhone 166, Mac 165 and Fire TV 167.

The rebuilt **Mira iPhone Updates helper 1.1.0 / 168** is universal ARM64/x86_64, macOS 13+. It:

- Falls back to a published manifest if Latest has no manifest, excluding drafts, prereleases and untrusted locations.
- Uses fresh network requests and rechecks cached IPA size/hash before offering installation.
- Rejects incorrect download hashes, malformed feeds and older builds than its own newer cached download.
- Removes failed temporary downloads and verifies a new IPA before replacing the cached one.

The helper was installed in Applications and opened on the development Mac. Its UI showed **Ready to install**, with Start at login still enabled. It did not trigger Sideloadly signing or install anything on the physical iPhone. [Helper ZIP](https://github.com/4marawan001/Mira/releases/download/v0.5.22/Mira-iPhone-Updates-macOS.zip) · [Source](../companion).

## iPhone source fixes, pending a new IPA

The new lookup/person profile feature is preserved. Its in-memory cache previously survived profile/account switches and could be repopulated by a late request from the old session. Cache reset now follows account/profile changes, writes carry a session generation, and immutable snapshots prevent concurrent mutable-map access. Old-session writes are rejected. The cache now stays at a strict maximum of 200 entries and copies caller-owned result lists.

General catalog search no longer silently broadens a multi-word query to its first word after an empty response. Initial search, View All and subsequent pages keep the same query. The separate person lookup remains in place. Provider capabilities still determine available matches.

The separate **v0.5.23** GitHub release’s IPA was inspected directly. It contains `com.nuvio.media`, **CFBundleVersion 165**, **CFBundleShortVersionString 0.5.22**, iOS 16.1 minimum, size **91,017,989 bytes**, SHA-256:

```text
4004c90b7e70b6f1c894b1d09f6d9576cc7fcfca75763d74b464751c3e26e4ed
```

Its build number is lower than the preceding iPhone 166 package. The old title and unmeasured “0ms” claims were corrected; the binary was not overwritten. If that package is already installed, keep it rather than switching solely because of the version table. Its source changes remain in the working checkout.

The next iPhone source version is **0.5.24 / 168**, with the lookup retained and the cache/query fixes above. This is a **Debug simulator preview**, not a published Release IPA. Local development instructions require reviewing the preview before final IPA packaging. The audit does not label source changes as already installed on the physical phone.

## Remaining checks and known issues

Previous broad suites retain two unchanged vendored Media3 failures on TV (HTTP error wrapping and allocator late release) and five desktop failures recorded in earlier reports. The selected suites above pass; this audit does not claim the broad suites are all green. The vendored TV engine source is not present in this workspace, so those engine failures are not presented as repaired.

Physical Insignia TV browsing/playback/account sync, physical Intel Mac GUI behavior, real-provider iPhone seeking and sustained device frame times remain unverified. No controlled frame-rate comparison was made. Provider metadata, HDR/audio/codec profiles, network speed, account services and signing restrictions can still affect the experience.

A [read-only channel validator](../tools/check-release-channel.py) and [publishing guide](RELEASING.md) now document the checks that prevent the update-channel and build-number mistakes from recurring. The guide requires preserving current lookup code, bundle identities, private data and other platforms’ manifest entries.
